# CID Automation

Playwright-based automation for creating/updating Course IDs (CIDs) on
Simplilearn's internal Simplex admin CMS. It walks a course through SEO,
Basic Details, Course Overview, Additional Content (Skills Covered), and
B2B SkillUp, and can run for a single course or a batch of courses from
an Excel file. Skills Covered and the Course Overview are generated by
analysing the course's TOC (Table of Contents) Excel file with a local
LLM (Ollama) - no cloud API calls, no per-run cost.

## Prerequisites

Install these on any machine you want to run this from:

1. **Python 3.10+** - https://www.python.org/downloads/
2. **Google Chrome**
3. **Git** (only needed to clone this repo) - https://git-scm.com/
4. **Ollama** (local LLM runtime, free) - https://ollama.com/download

## Setup

```powershell
# 1. Clone the repo
git clone https://github.com/2200030442karthik/cid-automation-.git
cd cid-automation-

# 2. Install Python dependencies
python -m pip install -r requirements.txt

# 3. Pull the local model used for Skills/Overview generation
ollama pull llama3.2:3b
```

Ollama runs as a background service after install (listens on
`http://localhost:11434`). No API key, no cost.

### Optional: OpenAI fallback

If local Ollama cannot produce a valid Skills/Overview result for a
course, the script can retry that one course on OpenAI
(`gpt-4.1-mini`, at most 3 calls per course and at most 3 courses per
run). It is used only when Ollama fails,
and only if an API key is set as an environment variable - never put
the key in the code:

```powershell
setx OPENAI_API_KEY "sk-..."
```

Open a new terminal afterwards so the variable is picked up. Without
the key, the script behaves exactly as before (Ollama only).

## Before every run

Chrome must be launched with remote debugging enabled, and you must be
logged into Simplex in that Chrome window - the script attaches to your
already-logged-in session rather than logging in itself.

```powershell
chrome.exe --remote-debugging-port=9222 --user-data-dir="%TEMP%\ChromeDebug"
```

Then log into `https://i9simplex.simplilearn.com` in that window and
leave it open.

## Running

```powershell
python main.py
```

You'll be asked to choose:

- **1. Single CID** - pick one course's TOC Excel file via a file
  dialog, then enter Primary Category, Primary EID, Course Level, and
  Duration when prompted.
- **2. Bunch of CIDs (batch Excel file)** - pick one Excel file listing
  multiple courses. Required columns (any order, case-insensitive):
  `Course Title`, `Primary Category`, `Primary EID`, `Course Level`,
  `Duration` (H:MM:SS), `TOC File Path` (path to that course's own TOC
  Excel file). A course row failing does not stop the batch - it's
  reported in the summary at the end, and processing continues with
  the next row.

## Other tools

All of these use the same logged-in Chrome session as `main.py`.
`logo_update.py` and `sunsettled.py` ask for **1. Single CID** or
**2. Bunch of CIDs** (CIDs separated by comma or space), and one CID
failing does not stop the rest.

- **`python logo_update.py`** - adds the `541 - Simplilearn_New` logo to
  existing CIDs: Basic page (Accreditation Heading + Accreditation
  Logos, max 2 allowed) and B2B SkillUp (Accreditation Configuration =
  Edit for SLH + Logos). Ticks "I have reviewed and validated the
  skills listed." if it is unticked. Both pages are reloaded to verify
  the save.
- **`python sunsettled.py`** - unlives CIDs: sets B2B SkillUp > Course
  Basics > Part of other product offering to **None** and submits.
  Nothing else is changed. Asks you to type `YES` before changing
  anything.
- **`python check_cid.py 8071 8072`** - read-only check of CIDs created
  by `main.py`; reports PASS/FAIL for each saved value. Never saves.

## Notes

- `unname.jpg` in this repo is a placeholder image used for the
  Course Logo, Certificate upload, and SLH thumbnails during
  automation - replace it if you want a different placeholder.
- The script never stores or commits your Simplex login session -
  `simplex_session.json` and `playwright_profile/` (created locally
  when you use them) are excluded via `.gitignore` and must never be
  committed; they contain live session cookies / saved browser
  credentials.
